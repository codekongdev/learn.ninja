A **brick** is one screen of a lesson. There are two families:

- **Concept bricks** teach: a short title, a few sentences, and often a visual.
- **Question bricks** practise: you answer, check, and get feedback.

Your agent picks each question brick by asking how a good teacher would test that point, not to fill a quota. Every brick below has a live demo you can play.

| Brick | You… | Good for |
| --- | --- | --- |
| [Concept](#concept) | read | One idea, with a visual, formula, or code |
| [Choice](#choice) | pick one or more answers | Facts, rules, predictions |
| [Compare](#compare) | pick the better of two | Judgement: which is clearer, safer, stronger |
| [Hotspot](#hotspot) | tap the right spot | Finding the problem in a UI, a document, or code |
| [Sort](#sort) | drag items into groups | Telling categories apart |
| [Order](#order) | drag items into order | Steps, sequences, ranking |
| [Match](#match) | link pairs | Words and meanings, terms and definitions |
| [Blank](#blank) | fill gaps with word chips | Sentences, formulas, code |
| [Scenario](#scenario) | choose what to do | Applying the idea to a realistic situation |

Every question brick has a **prompt** of up to 40 words, an **explanation** shown after a correct answer (on request) or once the answer is revealed, **feedback** on each wrong option that explains the mistake behind it, and an optional **hint** and **visual**. See [Lesson format](/docs/lessons/lesson-format) for every field.

## Concept

Teaches one idea in a few sentences, often with a visual, a formula, or code.

<BrickPreview lesson="compound-interest" brick="c1" />

A concept brick is the theory between questions. Each lesson has one to three of them, and each is followed right away by two to four questions that practise it.

### When to use it

- To introduce the idea the next questions practise.
- Keep it short: a title of up to 60 characters and a body of up to 80 words.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `title` | yes | Up to 60 characters |
| `body` | yes | Rich text, up to 80 words |
| `visual` | no | HTML, a formula, or code |
| `term` | no | A key word and its definition, shown as a callout |

## Choice

Pick one answer, or every answer that applies.

<BrickPreview lesson="button-hierarchy" brick="p1" />

The most common question brick. Two to five options, with one or more correct.

### When to use it

- Facts, rules, and predictions ("What does this log?").
- Numeric questions: v1 has no number input, so ask them as a choice whose wrong options come from real mistakes.
- Set `multiple: true` for "pick all that apply".
- Put a `visual` on the brick when the question is about something to look at, like a chart, a screen, or a diagram. It shows above the options.
- Give the options visuals when the answers themselves are something to look at: which layouts, charts, or components get it right.

### Fields

| Field      | Required | Description                                    |
| ---------- | -------- | ---------------------------------------------- |
| `options`  | yes      | 2–5 options, each with `text` or a `visual`    |
| `correct`  | yes      | Ids of the correct options                     |
| `multiple` | yes      | `true` to allow several picks, `false` for one |

Every wrong option needs `feedback` that explains the misconception.

### Visual options

When any option has a `visual`, the options show as cards in two columns, like [Compare](#compare), each labelled "Option 1", "Option 2", and so on. A `text` on an option becomes a short caption under its visual.

- Give every option a visual, so the cards line up and none of them stands out by format alone.
- Give every option a short `text` caption too. Screen readers can't see inside a visual, so the caption is what they announce.
- Keep each visual small and focused on the one difference that matters. Each must be under 20 KB.
- HTML visuals are static HTML, CSS, and inline SVG, with the built-in UI kit and Tailwind utilities. No JavaScript, and nothing loaded from an external URL, so no linked images or photos.
- On a phone, the cards stack in one column.

## Compare

Two options side by side; pick the better one.

<BrickPreview lesson="compound-interest" brick="p4" />

A compare brick puts exactly two options next to each other. It tests judgement rather than recall.

### When to use it

- "Which is clearer, safer, stronger, faster?"
- Good as the hook: a quick gut call before any teaching.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `options` | yes | Exactly 2 options, each with `text` or a `visual` |
| `correct` | yes | The id of the better option |

## Hotspot

Tap the right spot in a visual or a line of code.

<BrickPreview lesson="button-hierarchy" brick="p2" />

A hotspot brick shows a visual and asks you to tap the part that matters. Tappable areas are marked in the HTML with `data-hotspot`, or listed as lines of code.

### When to use it

- Finding the problem in an interface, a document, or a snippet of code.
- Set `multiple: true` when there's more than one spot to find.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `visual` | yes | HTML with `data-hotspot="id"` on tappable elements, or code with `hotspots` |
| `correct` | yes | Ids of the right spots |
| `multiple` | yes | `true` when there are several spots, `false` for one |

## Sort

Drag each item into the group it belongs to.

<BrickPreview lesson="writing-a-prd" brick="p3" />

A sort brick has two or more labelled groups and four to eight items. Drag each item into its group, or use the keyboard.

### When to use it

- Telling categories apart: goal or non-goal, `map` or `forEach`, formal or informal.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `groups` | yes | Each with an `id` and a `label` |
| `items` | yes | 4–8 items, each with `text` and the `group` it belongs to |

## Order

Put items in the right order.

<BrickPreview lesson="button-hierarchy" brick="p4" />

An order brick shuffles a list and asks you to put it back in order, by dragging or with the keyboard.

### When to use it

- Steps in a process, sections of a document, ranking by size or weight.
- Only when the order really matters. If two orders are both right, list the other in `alsoAccept`.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `items` | yes | The items, in the correct order |
| `alsoAccept` | no | Other orders that also count as correct |

## Match

Link each item on the left to its partner on the right.

<BrickPreview lesson="spanish-greetings" brick="p1" />

A match brick has three to five pairs. The right column is shuffled; link each left item to its partner.

### When to use it

- Words and meanings, terms and definitions, symbols and names.
- Set `leftLang` or `rightLang` when a column is in another language, so browsers and screen readers treat it as that language.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `pairs` | yes | 3–5 pairs, each with `left` and `right` |
| `leftLang`, `rightLang` | no | Language of a column, for language lessons |

## Blank

Fill the gaps in a sentence, formula, or code with word chips.

<BrickPreview lesson="map-vs-foreach" brick="p1" />

A blank brick has a template with one or more gaps, written `[[id]]`. You fill each gap by picking a word chip. v1 has no typed answers, so every gap has chips.

### When to use it

- Completing a sentence, a formula, or a line of code.
- Set `format: "code"` with a `language` for code, usually with `caseSensitive: true`.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `template` | yes | Text with `[[gap]]` markers |
| `blanks` | yes | For each gap: `accept` (right answers), `choices` (the chips), and optional `mistakes` with feedback |
| `format` | yes | `text` or `code` |

## Scenario

A realistic situation; choose what you'd do.

<BrickPreview lesson="button-hierarchy" brick="ch" />

A scenario brick sets up a situation and offers choices that are best, okay, or poor. After you choose, you see what happens next.

### When to use it

- Applying the idea to a realistic case, often as the lesson's final challenge.
- When there's a range of reasonable answers rather than one right fact.

### Fields

| Field | Required | Description |
| --- | --- | --- |
| `situation` | yes | The setup, in rich text |
| `options` | yes | Each with `text`, a `quality` (`best`, `okay`, or `poor`), and the `outcome` |

At least one option must be `best`.
